# OVERSPAM: общий документ проекта для агентов

Читают все агенты, кто работает в этом репозитории: Claude, Codex и другие. Здесь собраны стиль, дизайн, подача и правила совместной работы. Задачи и решения владельца лежат в `overspam/PLAN.md`, пайплайн и команды — в `overspam/README.md`.

## Проект

**OVERSPAM** — 3D survivor roguelite: 5 миров, 12 героев, «one ridiculous run». Сайт: overspam.com. Делаем маркетинг для Steam:

- **трейлер «этой осенью»**, 40–60 с. Сценарий владельца в `PLAN.md`, «Видео 1»;
- **обзорный ролик** 1,5–2 мин, «Видео 2»;
- **вставки** между кадрами геймплея (Remotion), прозрачные плашки поверх геймплея, концовка, капсулы Steam;
- **короткие вертикальные ролики** TikTok и Shorts для разогрева (позже).

Монтаж в CapCut делает **владелец сам**. От агентов нужны только вставки, плашки и графика, которые он не соберёт в CapCut, плюс промпты и планы.

## Визуальный стиль

**Общее ощущение:** пиксельная игровая графика поверх 3D-вокселей, тёмная сцена, тёплый золотой акцент. Весело, нагло, «слишком много всего», но читаемо за долю секунды.

### Цвета

| Роль | Цвет |
|---|---|
| Фон | почти чёрный `#07070d`. Вариант `deep`: плёночное зерно и виньетка, без сетки и цветных пятен |
| Главный акцент | золото `#ffc547`: рамки, свечение, ромбики-маркеры |
| Логотип и цифры | полосы сверху вниз от кремового `#fffae8` к персиковому `#ffba6a`, на `SPAM` уходят в оранжевый, бордовая толщина снизу `#62162c`, тёмная обводка `#090911` |
| Вторичный текст | белый (`white`) или приглушённый серо-голубой (`dim`, `#9aa0b8`) |
| Миры | Forest `#8fdc6a`, Moon `#6ff3ff`, Dead Internet `#ff4fd8`, Sunscar Dunes `#ffc547`, Abyss Dome `#3ff2e0` |
| Мобы против героев | мобы на красном свете (`rgba(255,50,65,…)`), герои на голубом (`rgba(60,205,255,…)`), переход между ними плавный, без линии |

### Шрифт и текст

- **Только игровой пиксельный шрифт**: `PixelText` (стили `logo`, `white`, `red`, `dim`) и `PixelLogo`. Системные шрифты в кадре не используем.
- Масштаб пикселя — **целое число**, иначе пиксели станут разной толщины.
- Текст на экране **английский, заглавными, коротко**: не больше 3–5 слов в строке. Цифры крупно (`logo`), подпись рядом мельче (`white`).
- Русский — для документов и общения с владельцем, в кадр его не ставим.

### Движение и ритм

- Всё на сетке музыки: **130 BPM**, доля 0,46 с, такт 1,85 с, 60 fps. Длины и тики считаются через `beatFrames(bpm)`. Если BPM меняется, правим `teaser.json` и перерендериваем.
- Появления на пружинах `SPAWN` (с перелётом) и `LAND` (мягкая посадка) из `kit.tsx`.
- Удар (импакт, «slam»): тряска `Camera`, звук `slam`, счётчик подпрыгивает. **Белую вспышку во вставках не ставим**: владелец её убрал, список `noFlash`. Вспышка осталась только в `build.mp4` и концовке.
- Тики звука на каждое появление (`TickSfx`), тон растёт к концу.
- Склейки и нарезки записей только по долям или полудолям.

### Подача

- Тон: весёлый, хвастливый, немного абсурдный («1 BUILD NOBODY PLANNED», «ONE RIDICULOUS RUN»).
- Каждая вставка = **одна мысль за 2–3 с**: число + слово (33 WEAPONS, 23 CARDS) или короткая фраза.
- Концовка по правилам Steam: логотип, одна строка про срок (`COMING THIS FALL`), одна кнопка `WISHLIST ON STEAM`, сайт. Чёрным кадром не заканчивать.
- Референс по монтажу — трейлер Deep Rock Galactic: Survivor (вставки-экраны между геймплеем, пауза перед боссом, вспышка и карточка в конце).

## Форматы выдачи

- Полноэкранные вставки: **MP4 H.264, 1920×1080, 60 fps** (`crf 14`).
- Всё, что кладётся поверх геймплея: **MOV ProRes 4444 с прозрачностью** (`*-alpha.mov`, `herotag-*.mov`, `maptag-*.mov`, `boss-*.mov`).
- Капсулы Steam: PNG, размеры в `CAPSULES` (`Capsule.tsx`), команда `npm run capsules`. Перед загрузкой в Steam размеры сверять в кабинете Steamworks.
- Новые записи геймплея: пережать командой из `footage/README.md`, файл ≤100 МБ.

## Как работать

- Перед правками согласовать **один кадр**: `npm run still -- <ID> key=value frame=N`. Полный рендер только после «да» владельца.
- Рендер: `npm run overspam -- <ID…>`. В облачном контейнере задать `REMOTION_BROWSER` с путём к установленному headless Chrome.
- Новая вставка = компонент + `*Frames(bpm)` + запись в `Compositions.tsx` + имя в `render` в `teaser.json` + строка в таблице `README.md`.
- Не коммитить: `out/`, `node_modules/`, случайные правки `package-lock.json` (npm разных версий переписывает поля `libc`).
- Коммит: по-английски, кратко, что и зачем.
- **Автор коммитов — владелец** (решение владельца 2026-11-02): `git config user.name "Yr4e"` и `git config user.email "121664451+Yr4e@users.noreply.github.com"`, агент указывается строкой `Co-Authored-By`. Иначе работа не засчитывается владельцу на GitHub.
- **Готовая работа уходит в `main`**: после задачи открыть pull request рабочей ветки в `main` и слить. GitHub засчитывает только коммиты основной ветки. Ветку `overspam-renders` (только бинарники для скачивания) в `main` не сливать.

## Гайд по движению (обязательно)

Перед любой новой вставкой прочитать **`overspam/MOTION_GUIDE.md`**. Там собрано, что владелец принял и что отверг, монтаж под звук, приёмы движения и порядок проверки. В документе есть кодовое слово для владельца.

## Скиллы и звук

- Скиллы перенесены из студии InputLag (`Yr4e/inputlag-studio`). Claude читает их из `.claude/skills/`, Codex — из `.agents/skills/`:
  - `remotion-*`: официальные скиллы Remotion. Начинать с `remotion-best-practices`, это роутер к остальным;
  - `remotion-motion-graphics`;
  - `editing-videos`: монтаж, ритм, звук, лицензии;
  - `animate`, `animation-vocabulary`, `review-animations`, `motion-brief-writer`: анимация и её проверка.
- **Звук:** правила и библиотека описаны в `overspam/SOUND.md`, список звуков с описаниями — в `content/overspam/sfx-library.json`. Перед тем как ставить звук, выбрать его по описанию оттуда.

## Работа двух агентов (Claude и Codex)

Владелец разрешил агентам общаться между собой. Общаемся **через репозиторий**:

1. **Перед работой:** `git pull --rebase origin overspam-teaser`.
2. **Взять задачу:** в `overspam/PLAN.md` дописать к пункту `(Claude, в работе)` или `(Codex, в работе)` и сразу запушить, чтобы второй агент не взялся за то же самое.
3. **Закончить:** отметить `[x]`, указать имя агента и файлы результата.
4. **Вопросы и передача работы** — в журнале ниже, новые записи сверху: дата, кто, что сделал, что осталось, вопросы второму агенту или владельцу.
5. **Чужой файл, который сейчас в работе у другого агента**, не трогать без записи в журнале.
6. **Решения владельца** записывать в `PLAN.md`, раздел «Решения владельца», с датой. Владельца не переспрашивать о том, что уже решено.
