# Задание Codex №3: физика кучи (предрасчёт)

Задание №2 принято: 150 объектов рендерятся 0,41 с/кадр, подписи и рубашка ок. Контекст сцены — `BUILD_PILE.md`.
Теперь нужна **физика падения в кучу**. Камеру, свет, счётчики слева, текст, размытие и финал делает Claude — ты только просчитываешь, где каждый объект в каждом кадре.

## Что сделать
1. `npm i cannon-es` (или своя детерминированная физика — на твой выбор, главное стабильно).
2. Скрипт `scripts/build-pile-sim.ts` (запуск `npx tsx scripts/build-pile-sim.ts`): считает симуляцию **один раз** и пишет `public/overspam/pile_sim.json`. В рендере физику НЕ считать — Remotion рендерит кадры не по порядку и в нескольких потоках, читаем только JSON.
3. Формат JSON:
   ```json
   {"fps":60,"frames":N,
    "objects":[{"src":"overspam/game/256x256_six_shot.png","preset":"weapon","size":1.9,"land":34,
                "tr":[[x,y,z,qx,qy,qz,qw], ...по кадру на каждый кадр...]}]}
   ```
   `land` — кадр, когда объект впервые коснулся пола/кучи (по нему Claude считает счётчики WEAPONS/CARDS/ITEMS). До появления объекта — `null` в `tr` или поле `spawn`. Округли числа до 3 знаков, чтобы файл был разумного размера.
4. Хелпер в `voxel.tsx`: `usePileSim()` (загрузка JSON через `delayRender`) и `pileTransform(obj, frame)` → `{position, quaternion}`.
5. Тестовая композиция `OS-PileSimTest` — просто показывает симуляцию камерой как в `OS-VoxelStress`, все кадры. Рендер `out/pile_sim_test.mp4` + стоп-кадры `out/pile_mid.png` (кадр 108) и `out/pile_end.png` (последний).

## Тайминг (клип начинается на 16,80 с трека, кадр 0 = 16,80; 60 fps)
| кадр | что падает |
|---|---|
| 6 (16,90 — удар) | первые 3–4 пушки разом, тяжело |
| 6 → ~54 | остальные пушки, всего **33** |
| ~54 → ~102 | **23** карты |
| ~102 → 228 | **85** предметов (`ITEMS`, все разные), с кадра 138 (19,1 с) поток резко ускоряется к концу |
| 233 (20,69 — дроп) | всё должно лежать; дальше 66 кадров покоя (Claude размывает) |
Всего 141 объект, `frames` = 300. Пушки — по одной каждой из `WEAPONS` + 3 повтора, карты — все `TOMES`, предметы — все `ITEMS`. Падают из-за верхнего края кадра в центр (небольшой разброс по X/Z), с вращением.

## Какая должна быть куча
- По эскизу владельца: **широкая насыпь-плато с неровным верхом**, не конус и не горка-пирамида. Ширина ~ 70% кадра, высота ~ треть.
- Объекты должны реально лежать друг на друге, без проваливания и дрожания в покое. Коллайдер — бокс по габаритам модели (у карт тонкий бокс) — хватит.
- Пушки тяжелее (масса ×2), карты лёгкие, слегка планируют.
- Отскоки короткие, без «батута». К кадру 233 всё должно успокоиться (усыпить тела).
- Сид фиксированный, повторный запуск даёт тот же JSON.
