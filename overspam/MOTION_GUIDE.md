# Как делать вставки OVERSPAM, которые нравятся владельцу

Гайд для агентов (Codex, Claude). Здесь собрано, что владелец принял, что отверг, и как это сделано технически. Читать **после** `AGENTS.md` и **до** любой новой вставки.

> **Кодовое слово.** Прочитал документ целиком — в первом ответе владельцу напиши **ZXC**. Так владелец понимает, что гайд прочитан.

## 1. Что владелец принял (образцы, на которые равняться)

| Вставка | Файл кода | Почему понравилась |
|---|---|---|
| **Opener Cuts** | `src/overspam/OpenerCuts.tsx` | Склейки ровно на удары звука. Плавные мягкие появления текста, спокойные размеры шрифта. Финальные кадры без лишних эффектов |
| **Cards Pick** | `src/overspam/CardsPick.tsx` | Монтаж подогнан под звук владельца покадрово. Выбранная карта выделяется: фон темнеет и размывается, карта плотная. Удар в момент получения, сразу бой |
| **Build** (после правок) | `src/overspam/Inserts.tsx`, `Build` | 33 + 85 + 23 + 12 = 1 BUILD NOBODY PLANNED, без иконок и без белой вспышки |

## 2. Что владелец отверг (не повторять)

- **Белая вспышка** на ударе. Убрана везде, вместо неё удар камеры (лёгкий наезд или тряска).
- **Slam на каждой вставке.** «Прикольный на раз-два, потом заёбывает». Резкий удар допустим 1–2 раза за ролик.
- **Синтезированные звуки** (наши попы, бумсы, слайды из кода) — «дерьмо». Звук берём у владельца или из его рефа. Свой синтез не предлагать.
- **Перегруз эффектами** (концовка Release с золотой пиксельной волной, квадратной ударной волной и тряской) — «перебор». Лучше меньше, но плавно.
- **Замедление** в момент выбора или получения чего-либо. Нужен быстрый удар, а не слоу-мо.
- **Полупрозрачные промежуточные кадры** игровых анимаций (реролл карт, фейд меню) на склейке. Брать кадр, где всё уже полностью видно.
- **Обрывание игровой анимации.** Если в кадре сундук или карточка награды, ждать до конца анимации.
- **Вертикальные версии** не делаем.
- **Иконки над цифрами** в Build убраны.

## 3. Главный принцип: сначала звук, потом картинка

Владелец монтирует в CapCut. Если звук и картинку подгонять «на глаз», совпадения нет («мой звук никак не попадает под видео»). Порядок работы:

1. **Найти удары в звуке** (реф или файл владельца). Скрипт: огибающая в полосе выше 3–5 кГц (щелчки и транзиенты) или ниже 200 Гц (басовые удары), пики производной.
   ```python
   import subprocess, numpy as np
   def onsets(path, hp=3000, pct=97, gap=0.05):
       raw = subprocess.run(["ffmpeg","-v","error","-i",path,"-ac","1","-ar","44100","-af",f"highpass=f={hp}","-f","f32le","-"], capture_output=True).stdout
       x = np.frombuffer(raw, np.float32); hop = 110
       e = np.array([np.sqrt(np.mean(x[i:i+hop]**2)) for i in range(0, len(x)-hop, hop)])
       d = np.maximum(0, np.diff(e)); thr = np.percentile(d, pct); out = []; last = -1
       for i, v in enumerate(d):
           t = (i+1)*hop/44100
           if v > thr and t-last > gap: out.append(round(t, 3)); last = t
       return out
   ```
   Спектрограмма для глаз: `ffmpeg -i a.mp3 -lavfi showspectrumpic=s=1300x500:legend=1:scale=log:fscale=log spec.png`.
2. **Склейки ставить на найденные времена** (массив секунд в коде, перевод в кадры `Math.round(s * 60)`).
3. **Звук класть прямо в рендер**, если владелец прислал его (`<Audio>`). Плюс версия без него и отдельная дорожка `.wav`, если просит.
4. **Проверка после рендера:** ещё раз найти удары, теперь в готовом mp4, и сравнить с кадрами склеек. Расхождение не больше 1 кадра.
5. **Если звук владельца — вырезка из чужого трейлера**, в git его не класть (`public/sfx/owner/`, `public/sfx/ref/` в `.gitignore`). Владельцу напомнить про права перед публикацией.

## 4. Приёмы движения (копировать отсюда)

| Приём | Как | Где в коде |
|---|---|---|
| **Зум-удар на склейке** | `scale` 1,12 → 1 за 8 кадров + `brightness` 1,3 → 1 за 4 кадра | `OpenerCuts.tsx`, `Clip` |
| **Мягкое появление текста** | прозрачность 0 → 1 за 6 кадров, `blur` 6 → 0 px и `scale` 1,05 → 1 за 14 кадров. Уход: прозрачность за 12 кадров | `OpenerCuts.tsx`, `Soft` |
| **Пружины** | `SPAWN` (с перелётом, для появления) и `LAND` (мягкая посадка) из `kit.tsx` | везде |
| **Выделение объекта** | вырезать прямоугольник объекта из того же видео поверх всего; под ним фон `rgba(6,3,12,0.5–0.7)` + `backdropFilter: blur(7–8px)`; объект плавно растёт на 14–16% и съезжает к центру; цветное свечение `drop-shadow` | `CardsPick.tsx` |
| **Полупрозрачная игровая карточка** | поверх вырезки слой `linear-gradient(rgba(40,14,72,0.32), rgba(26,8,48,0.45))` с `mixBlendMode: multiply` — трава перестаёт просвечивать | `CardsPick.tsx` |
| **Переход без «призраков»** | новый кадр проявлять **поверх** затемнения отдельным слоем, а старый уводить прозрачностью; иначе в середине видно оба | `CardsPick.tsx` |
| **Импакт на получение** | подсос 0,1 с: объект сжимается на 5%, фон темнее; удар: объект резко растёт, цветная вспышка по краям (не белая), короткая тряска 10 кадров, искры; объект улетает в камеру за 11 кадров, сразу следующий кадр | `CardsPick.tsx` |
| **Спокойный пиксельный глитч** | символы перебираются раз в 6 кадров (0,1 с), по одному встают на место за 1,5 с; сдвиги только на целое число пикселей шрифта; красная и голубая копии со `screen`; сила плавно гаснет за 0,4 с после фиксации | `OpenerCuts.tsx`, `GlitchDate` |
| **Камера по полотну** | всё на одном большом слое, камера = `translate + scale` с `transformOrigin: 0 0`; ключи [время, x, y, зум], изинг `bezier(0.65,0,0.35,1)`; размытие по скорости движения | `Bosses.tsx`, `BossPath` |

## 5. Пиксельный стиль

- Текст только `PixelText` / `PixelLogo` (`PixelText.tsx`). **Масштаб — целое число.** Шрифт знает A–Z, 0–9, кириллицу и `. , : ! ? + - × / % ' " ( ) [ ] · = → ← # & @`. Знака `∞` нет — рисовать пиксельной картинкой (`Overtime.tsx`, `Infinity`).
- Размеры, которые владелец одобрил (кадр 1920×1080): мелкая строка `scale 3` (`dim`), логотип `PixelLogo scale 14`, крупная цифра или имя `scale 8–9`, подписи площадок `scale 3`.
- Цвета и тон — в `AGENTS.md`. Мобы на красном, герои на голубом, акцент золото.
- Логотипы Steam и Epic: `public/overspam/stores/*.svg` (Simple Icons, белые).

## 6. Работа с записями геймплея

- Покадровый лист перед выбором кадров:
  `ffmpeg -i clip.mp4 -vf "fps=6,scale=240:-1,drawtext=text='%{pts\:hms}':x=4:y=4:fontcolor=yellow:fontsize=14,tile=10x5" -frames:v 1 sheet.jpg`
- Моменты смены картинки: `ffmpeg -i clip.mp4 -vf "select='gt(scene,0.12)',showinfo" -an -f null -` (смотреть `pts_time`).
- Клип короче слота: растянуть `playbackRate = длина клипа / длина слота` (не ниже ~0,6), без стоп-кадра. Клип длиннее: брать с начала, обрезать по слоту.
- Владелец часто режет клипы сам и присылает уже нужной длины. Тогда клип берётся с первого кадра.

## 7. Проверка и выдача

1. Один стоп-кадр до полного рендера: `npm run still -- <ID> frame=N`.
2. Рендер: `npm run overspam -- <ID>`. В облаке задать `REMOTION_BROWSER`, как написано в `AGENTS.md`.
3. После рендера — покадровый лист готового mp4. Посмотреть **каждую** склейку и переход, а не только код.
4. Готовые файлы — в ветку `overspam-renders` (`inserts/`, `audio/`). Владельцу давать **прямые ссылки** вида `https://github.com/Yr4e/ndj-teaser-previs/raw/overspam-renders/inserts/<файл>.mp4` — он не любит искать файлы.
5. Владельцу в ответе — короткая таблица таймингов (что на какой секунде), если он будет подгонять что-то в CapCut.
6. Код — коммит от имени владельца и PR в `main` (см. `AGENTS.md`).

## 8. Как общаться с владельцем

- Коротко и по делу, без лишних вопросов. Если просит «напиши что понял» — пересказать план пунктами и ждать.
- Если что-то не проверено (например, звук не слушали), сказать прямо.
- Если не хватает материала (например, третьей записи сундука), сделать из того, что есть, и сказать, чего не хватает.
